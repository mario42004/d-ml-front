## Decisiones importantes

### Contrato limpio de métricas

La API debe devolver un análisis rico en features, pero sin contradicciones ni bloques legacy que ensucien el JSON.

Se acordó:

- No usar un bloque grande de metadata en el front.
- Mantener métricas canónicas bajo `metricas.grupos`.
- Evitar mostrar datos técnicos que no aportan lectura operativa.

### Descripción obligatoria del audio

El front pide una descripción corta obligatoria:

- Campo: `audio_description`
- Máximo: 50 caracteres
- Se guarda en `audio_jobs.audio_description`
- Se incluye en CSV como `descripcion_audio`
- Se muestra en historial, detalle, dashboard y autocorrelación.

La API también acepta `audio_description` y la usa dentro del PNG:

- `Audio Analysis Dashboard: {descripcion}`
- `Autocorrelation: {descripcion}`

### SNR

El usuario cuestionó correctamente que no puede calcularse un SNR físico real sin conocer potencia de ruido.

Decisión:

- Presentarlo únicamente como `SNR estimado`.
- No explicar como si fuera una medición física absoluta.
- En API, la descripción quedó como `SNR estimado.`
- En front, la tarjeta dice `SNR estimado`.

### Dashboard de la API

El dashboard API quedó así:

- Arriba izquierda: waveform completa.
- Arriba derecha: zoom de señal de 1.5 segundos con envolvente superpuesta.
- Abajo izquierda: average spectrum limitado a 0-2500 Hz.
- Abajo derecha: mel spectrogram.

Se quitó del dashboard principal el panel de RMS Energy porque no aportaba lectura suficiente.

La visual individual `rms_energy` sigue existiendo por compatibilidad.

## Persistencia y trazabilidad

La persistencia de Audioprint queda una fila por audio/análisis.

Tablas Audioprint:

- `audio_jobs`
- `audio_job_metrics`
- `audio_job_feature_snapshots`

CSV:

- Debe devolver un audio por fila.
- Solo audios del usuario activo.
- Admin/super puede consultar toda la tabla.
- Identificador útil: `analysis_id` / `audio_job_id`.

## Plataforma genérica de análisis

Se implementó una capa común para futuras APIs:

- `analysis_engines`
- `analysis_jobs`
- `analysis_metrics`
- `analysis_feature_snapshots`
- `analysis_artifacts`

Motivo:

- El equipo tendrá al menos dos APIs nuevas:
  - una de machine learning
  - una de descomposición wavelets

Decisión:

- Audioprint sigue funcionando con sus tablas actuales para no romper producción.
- Pero los análisis nuevos también se registran en `analysis_*`.
- Audioprint queda como primer motor:
  - `audioprint_wavelet`

Se creó `/portal/analisis.php`, pero se retiró la pestaña visible `Análisis` porque generaba confusión en la navegación principal.

La infraestructura queda debajo, lista para usar, sin competir visualmente con Audioprint.

## Bug corregido

Bug:

- Al eliminar un audio fallido o incompleto, se borraba el registro pero luego aparecía error 500.

Causa probable:

- `scalogram_path` vacío hacía que `audioprint_analysis_path_from_scalogram_path()` devolviera `null`.

Fix:

- Validar que la ruta sea string no vacío antes de `is_file()`.
- Borrar también el `analysis_job` genérico asociado para evitar huérfanos.

Archivo:

- `includes/audioprint.php`

Estado:

- Subido a producción.
